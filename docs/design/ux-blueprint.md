# KnowGate UX 蓝图

## 1. 设计结论

KnowGate 不是课程目录，也不是成人学习仪表盘。它是一款面向小学阶段学生的能力闯关应用，核心体验是：

```text
进入年级世界 -> 选择当前小关 -> 完成短章节 -> 挑战 Boss -> 查看掌握度 -> 补强薄弱节点
```

设计目标：

- 首次使用者 10 分钟内进入并完成第一次 Boss 战。
- 学生始终知道“我在哪里、下一关是什么、为什么现在做这一步”。
- Boss 失败后进入具体知识节点的补强，而不是整关重来。
- 家长报告和成长数据服务于理解和复习，不制造公开排名或焦虑。

设计验证来源：

- `ui-ux-pro-max` 产品匹配：Educational App、Kids Learning、Casual Puzzle Game。
- 主风格：Claymorphism + Vibrant & Block-based + Micro-interactions。
- 可访问性与交互约束：44x44 触控目标、清晰焦点、颜色非唯一表达、减少动态效果、可暂停或延长倒计时。

## 2. 目标用户

### 主用户：学生

| 维度 | 设定 |
|---|---|
| MVP 年龄 | 小学三至四年级，约 8 至 10 岁 |
| 使用设备 | 手机和竖屏平板优先，桌面浏览器兼容 |
| 使用场景 | 课后 15 至 30 分钟、家长陪伴、课堂练习 |
| 主要动机 | 过关、看到 Boss 被击败、获得星级和徽章 |
| 主要阻力 | 阅读负担、倒计时焦虑、失败后不知道补什么 |

### 次用户：家长

- 查看完成情况、掌握节点、待补节点和复习建议。
- 不查看公开排名，不直接替学生跳过前置知识。
- 可决定是否使用学习模式、延长倒计时或减少动效。

### 后续用户：教师

- 查看班级完成情况和内容质量。
- 组卷、布置复习、审核内容。
- 教师端不是 MVP 的第一套主界面。

## 3. 体验原则

1. **下一步永远明显**
   世界地图和每个详情页只突出一个主行动：继续当前章节、查看知识点或发起 Boss 挑战。

2. **先学习，再战斗**
   Boss 按钮在章节完成后解锁。锁定状态说明缺失条件，不显示模糊的“暂不可用”。

3. **失败给出路径**
   战斗结算必须把失败连接到知识节点、最短补课和直接重打，而不是只显示“失败”。

4. **掌握度替代分数焦虑**
   学生看到节点掌握度、错因和下一步，不看到班级排名或“差生”标签。

5. **游戏感来自进度和反馈**
   使用地图、Boss、连击、伤害和徽章表达进展；不使用随机抽卡、付费跳关或赌博式奖励。

6. **低龄可用且不过度幼稚**
   形状、颜色和文案友好，但布局、可读性和交互逻辑保持专业，不使用装饰性 emoji 图标。

## 4. 信息架构

```text
知关
  -> 年级世界
    -> 小关地图
      -> 小关详情
        -> 章节
          -> 钩子
          -> 概念
          -> 范例
          -> 跟做
          -> 独立练习
          -> 短测
        -> Boss 说明
        -> Boss 战斗
        -> 结算
        -> 补课
  -> 成长
    -> 节点掌握度
    -> 待复习
    -> 徽章
  -> 设置
    -> 学习模式
    -> 倒计时
    -> 减少动态效果
    -> 音效与触感
```

MVP 底部导航只保留三项：

| 导航 | 目的 |
|---|---|
| 闯关 | 默认首页，进入地图和当前小关 |
| 成长 | 查看掌握度和复习建议 |
| 设置 | 控制学习模式、倒计时、动效和音效 |

## 5. 核心旅程

### 5.1 首次进入

1. 展示年级世界和 10 个小关总览。
2. 自动定位第 1 关，并给出 `开始第 1 关`。
3. 第 1 关详情只展示 3 至 5 个章节和 Boss 说明。
4. 完成章节短测后，主按钮切换为 `发起挑战`。
5. 完成第一次 Boss 后，结算页展示掌握度变化和下一关。

### 5.2 进入小关

```text
地图点击小关
  -> 查看目标节点
  -> 查看章节清单
  -> 继续未完成章节
  -> 完成章节后解锁 Boss
  -> 进入 Boss 说明
```

### 5.3 Boss 战

```text
Boss 说明
  -> 选择标准模式或学习模式
  -> 开始战斗
  -> 读题、答题、结算伤害
  -> 胜利 / 失败 / 决胜题
  -> 结算页
```

战斗界面必须同时展示：

- Boss 名称、血量、剩余距离。
- 当前题目、时间档、输入区域。
- 连击、提示入口、暂停或退出。
- 正确答案反馈、解析、对应知识节点。

### 5.4 失败与补课

```text
Boss 失败
  -> 识别错误节点
  -> 展示 1 至 3 条最短补课路径
  -> 完成补强练习
  -> 返回 Boss 说明
  -> 直接重打
```

补课页只显示未掌握节点和必要前置节点，不展示完整课程树。

## 6. 页面规范

### 6.1 世界地图

目标：让学生在一屏内理解 10 个小关的整体进度和当前行动。

结构：

- 顶部：世界名称、关卡进度、总掌握度摘要。
- 主体：10 个小关形成可读路径。
- 当前小关：视觉强调，并附 `继续闯关`。
- 已完成小关：显示星级和最佳结果。
- 锁定小关：显示前置条件文本。

小关节点状态：

| 状态 | 表达 |
|---|---|
| 已完成 | 实心节点 + 对勾 + 星级 |
| 进行中 | 放大节点 + 进度环 + `继续` |
| 可开始 | 实心节点 + 入口标记 |
| 已锁定 | 线框节点 + 锁形图标 + 前置说明 |
| Boss 已胜 | 节点尾部显示胜利徽记 |

移动端：地图可纵向滚动，当前节点自动居中。

桌面端：地图约 60% 宽度，右侧显示当前小关详情；不要把所有区块做成悬浮卡片。

### 6.2 小关详情

目标：让学生确认学什么、学到了哪里、何时可以挑战。

结构：

1. 小关标题和 Boss 主题。
2. 目标知识节点。
3. 章节进度列表。
4. Boss 准备状态。
5. 单一主行动。

章节点状态：

- `未开始`
- `学习中`
- `已完成`
- `短测未通过`

主按钮规则：

| 条件 | 主按钮 |
|---|---|
| 有未完成章节 | `继续第 N 章` |
| 章节完成但短测未过 | `复习短测` |
| 全部条件满足 | `发起挑战` |
| Boss 已胜利 | `重打或进入下一关` |

### 6.3 章节页

目标：把 3 至 8 分钟微学习变成清晰的单步任务。

固定阶段：

1. 钩子。
2. 概念。
3. 范例。
4. 跟做。
5. 独立练习。
6. 2 至 4 题短测。

页面规则：

- 同一时间只突出一个核心任务。
- 顶部显示章节阶段进度，不使用模糊的百分比圆环。
- 每个阶段都有明确定义的 `继续` 按钮。
- 答错时先给提示，再给解析，不直接跳走。
- 离开章节前保存进度。
- 学习模式下短测阈值可降至 60%，但前置节点不能被跳过。

### 6.4 Boss 说明页

目标：在开始倒计时前解释规则和风险。

必须展示：

- Boss 名称、主题和目标节点。
- Boss 血量、距离、失败条件。
- 题目数量和时间档。
- 标准模式与学习模式差异。
- `开始挑战` 和 `返回复习`。

标准模式默认选中，但首次学习建议突出学习模式。

### 6.5 Boss 战斗页

视觉层级：

1. Boss 血量和逼近轨道。
2. 题目和输入区。
3. 倒计时、连击、提示和草稿。
4. 暂停或退出入口。

反馈规则：

| 事件 | 反馈 |
|---|---|
| 答对 | 伤害数字、Boss 受击、连击更新 |
| 答错 | Boss 前进、错误节点标签、解析 |
| 超时 | Boss 前进、说明超时原因 |
| 连击 | 第 3 题和第 5 题强化伤害，并显示文本 |
| 胜利 | Boss 血量归零、结算入口 |
| 失败 | 距离归零、补课入口 |

低焦虑规则：

- 学习模式超时不推进 Boss。
- 倒计时可暂停、延长或关闭。
- 动画不能替代文字状态。
- 切后台暂停，返回后给 1 秒缓冲。

### 6.6 结算页

目标：把一次战斗转化为清楚的掌握度反馈。

结构：

- 胜负结果和星级。
- 正确率、用时、连击、伤害。
- 节点掌握度变化。
- 错误节点和错因。
- 下一步行动。

胜负后的按钮：

| 结果 | 主按钮 | 次按钮 |
|---|---|---|
| 胜利 | `进入下一关` | `查看知识点` |
| 失败 | `开始补课` | `重新挑战` |
| 决胜题胜利 | `进入下一关` | `复盘错题` |

### 6.7 补课页

目标：只修复低掌握节点，不重复已经掌握的内容。

结构：

- 错误节点和当前掌握度。
- 最短前置路径。
- 1 至 3 个针对性练习。
- `补强完成` 后返回 Boss。

文案避免责备，例如：

- `先补强这个节点`
- `再练 3 题就能重打`
- `你已经掌握 2 个前置节点`

## 7. 交互状态

所有页面至少覆盖：

- 加载中：保留布局的骨架屏或简短状态。
- 空状态：说明为什么为空和下一步。
- 锁定状态：说明缺少什么。
- 离线状态：战斗答案本地排队，提示同步状态。
- 断网恢复：恢复服务端战斗状态。
- 内容版本变化：进行中的战斗继续使用开始时的版本。
- 提交中：按钮显示进度并防止重复提交。
- 错误：错误靠近字段或交互区域，不只显示顶部通知。

战斗按钮在提交答案后立即禁用，直到服务端返回裁决。

## 8. 无障碍

- 所有交互目标至少 44x44 CSS px。
- 计时器使用可读数字、进度语义和 `aria-live` 更新。
- Boss 距离同时使用图形、数字和文字表达。
- 正确、错误、锁定、完成状态不能只依赖颜色。
- 支持完整键盘操作和清晰的 2 至 4px 焦点环。
- 支持系统字体放大，文字不可截断关键内容。
- 支持 `prefers-reduced-motion`，关闭伤害数字、抖动和大幅位移。
- 模态框和底部栏不能遮挡焦点控件。
- 可自动变化的倒计时和动画内容提供暂停或关闭。

## 9. 文案规则

推荐：

- `继续闯关`
- `先学 3 个短章节`
- `Boss 还剩 4 步`
- `先补强这个节点`
- `掌握度 +12`
- `连击 3，额外伤害 +1`

避免：

- `快一点，否则失败`
- `你太慢了`
- `差生题`
- `刷题`
- `免费跳过`
- `班级第 N 名`

## 10. 设计验收

进入开发前检查：

- 首次用户在 10 分钟内理解并能进入 Boss。
- 学生可以解释 Boss 为什么前进。
- 失败后能指出至少一个对应知识节点。
- 世界地图在 375px、768px、1024px 和 1440px 均无水平滚动。
- 所有状态都有文字表达。
- 学习模式可以从 Boss 说明页或设置页进入。
- 减少动态效果不会改变任务结果。
